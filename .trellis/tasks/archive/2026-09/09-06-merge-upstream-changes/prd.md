# 合并原项目代码变更

## Goal

将 `upstream/main`（原项目 `Liuuuu54/st_bs_biotracker`）在共同基线之后的实际代码改动合并到当前本地 `main`，让本地项目获得原项目的功能、修复、界面、文档和测试，同时保留本地分支已有且不属于原项目的功能。

## Background and confirmed facts

- 当前本地仓库的 `origin` 是 `tianwuziyan/st_bs_biotracker`，`upstream` 是原项目 `Liuuuu54/st_bs_biotracker`。
- 双方共同基线为 `088313796b2c11528447712b751409d4f782c0bc`；任务开始前工作区干净。
- 原项目同步到 `c83afcc7827f9f5e00afa4aff550d53dadcccff1`，基线之后约有 50 个提交，改动横跨核心脚本、UI、样式、文档和测试。
- 本地基线之后保留了历史消息正则、外部历史记忆、分析楼层快照/尾部恢复、自然受精和追踪/UI 修复等本地功能。
- 双方产品版本均为 `0.9.7`。版本号不是本次合并的判断依据；不得因为版本号相同而忽略内容，也不因上游版本元数据而擅自升级版本。

## Requirements

### R1. 合并原项目核心功能和修复

纳入原项目在共同基线之后的核心行为变更，包括但不限于：

- 胎儿来源标签、稳定 child id、父系种族和族谱数据模型；
- 异期复孕、孕中孕、胎内回归、特殊胎儿来历注册及其生命周期校验；
- user 巨集解析、工具说明/参数契约、精液残留提示和原项目的工具层修复；
- API 代理 User-Agent、提示词上下文和状态迁移/兼容逻辑。

合并后这些行为要与本地已有的状态快照、注册、追踪、自然受精和历史上下文流程相容，不能通过简单覆盖丢失本地修复。

### R2. 合并原项目 UI 和样式改动

纳入原项目的族谱窗口、胎儿来源展示、精液来源占比环、孕期衣着压力量表、年龄展示、Sakura 更新和 iPhone 主题/配色/字体设置，并保留本地正则界面、记忆来源设置、权重显示和其他现有页面行为。

### R3. 保留本地专属功能

合并完成后，本地以下功能必须仍存在并可运行：

- `scripts/history_regex.js`、`scripts/message_regex.js`、`scripts/memory_sources.js` 及对应设置和提示词接入；
- tracker 楼层 checkpoint、尾部删除恢复、手动重分析基线及失败回滚；
- 自然受精结算、洗漱/擦拭判定、同时判定和本地 UI 权重修复；
- 本地已有测试、文档和宿主兼容逻辑。

### R4. 合并文档但不以版本号制造差异

合并 `README.md`、`Changelog.md` 中描述实际行为的内容，必要时同步现有 `docs/` 文档；保留当前项目的文档结构和本地未发布记录。版本号、版本 URL 参数和 manifest 版本字段仅在确有非版本语义差异时处理，不为了“追上游”改变产品版本。

### R5. 保留并补齐验证覆盖

保留双方已有测试，纳入原项目新增测试；对冲突后的公共接口、状态字段、提示词、注册和 UI 契约进行回归验证。测试失败时必须区分合并冲突导致的回归、原有环境问题和无关问题，不能用删除测试规避失败。

### R6. 合并过程可追溯且不外发

使用共同基线进行可追溯的三方合并，解决冲突后保留合并结果和验证记录；只修改当前本地工作区并可创建本地 Git 提交，不向任何远端 push，不记录密码、Token 或 API Key。

## Out of scope

- 不把版本号或 Changelog 的版本标题当作功能差异依据。
- 不删除本地专属功能、测试或文档来降低冲突数量。
- 不重写与本次合并无关的业务逻辑，不新增未出现在双方代码中的产品功能。
- 不修改远端仓库、远端分支或发布配置，不进行部署。
